1. What’s changed since last year?

Before highlighting things that changed, I want to talk about one that didn't: Java's steady progression.

JDKs 26 and 27 were released like clockwork on the schedule set nine years ago, in March and September 2026, respectively.
Both releases ship approximately 10 JDK Enhancement Proposals (JEPs) as well as hundreds of small changes, from API and runtime refinements to bug fixes, from performance improvements to security patches.
If you visit inside.java and scroll over the landing pages, you will see just how multi-faceted and thorough this technical progression is.

That said, let's look at a few things that _did_ change.
First, two items that primarily impact Oracle JDK, but can (and in my personal opinion likely will) also manifest in other JDK distributions:

* Over the course of 2027, Oracle JDK intends to adopt a monthly cadence for security updates.
* Post-quantum cryptography is planned to be backported to all Oracle JDKs with LTS.

In light of the increased speed and scale of software vulnerability discovery and remediation through AI, as well as the spectre of harvest-now-decrypt-later attacks that expect quantum computers to eventually be able to decrypt most currently available encryption, these two changes are intended to strengthen the security capabilities available to Java developers.

But, while essential, I have to admit that these two items aren't exactly thrilling.
What really excites me is the progress in various OpenJDK projects:

* Project Leyden generalized its class loading and linking strategies to work with any garbage collector in JDK 26 and merged the capability to include AOT-compiled machine code in its cache into the JDK main line in August, which makes it available in the JDK 28 early-access builds.
* Project Lilliput shored up compact object headers and made them the default in JDK 27.
* Project Valhalla finally made its first feature available, namely value classes, which are also available JDK 28 early-access builds.
* Project Babylon published promising demos and white papers and is polishing its code reflection prototype for incubation.
* Project Amber is making progress towards its next steps and Brian Goetz published ideas for deconstruction patterns for regular classes.

As I said at the top, there are of course more things happening than "just" these big-ticket projects and not all of them are additions, either. To mention just two clean-up steps in JDK 26:

* Applets were removed.
* Warnings are issued if reflection is used to mutate final fields.

All in all, basically every aspect of Java saw changes in the last year.



2. What's new and exciting that we didn't expect?

Amidst all the aforementioned developments, one that surprised me is how far OpenJDK's consideration of limited operator overloading has progressed.
As the conversation currently stands, a concept called _type classes_ is being explored as an approach that could allow developers to define operations like `+` and `*` but also type conversions or bit-shifting for value classes.
This would allow a natural expression of arithmetic for custom numeric types while preventing some of the questionable outgrows of general operator overloading, where, in the most flexible (and arguably worst) case, developers can define what the operation `<%<` means for their `UserService` type.

Another surprise to me was the Modern Java in the Wild online hackathon my newest colleague Sophia Minaya organized within just a few months of joining the Java Developer Relationship team at Oracle.
Here's her summary of how it went:

> Modern Java in the Wild invited developers in the U.S. to get creative with Java 26, building projects around the themes of Home, Health, and Hobby while competing for a prize pool of more than $4,000.
> In partnership with the Hackster community, we brought developers together to experiment, build, and show off what modern Java can do and received more than 100 creative project submissions!
> This was just our first competition, and we're looking forward to creating more challenges that bring our community together, especially on a global scale.
> Stay tuned for our next challenge, and in the meantime, join our Java community hub on Hackster to check out the winning submissions and show off what you’re building with modern Java!

Lastly, I was not prepared for the revelation that OpenJDK would take another swing at better integration with JavaScript and Python.
The freshly unearthed Project Detroit will use the established `javax.script` API but, unlike earlier efforts, aims at merely wrapping existing runtimes, namely Chrome V8 and CPython.
As it sounds, progress is quick.



3. What's getting you, personally, really excited in the Java space?

Given that I spend almost all my time following and sharing Java's evolution in OpenJDK, what excites me personally comes from that realm, too:
It's value types, deconstruction, withers (eventually 🤞), ahead-of-time computation, etc.
One comparatively simple addition that is nonetheless exciting just because it will come in handy so often is the new JSON API that will be incubating in JDK 28 (and is already available in the EA builds).
It will be a great starter pack to parse, traverse, and format JSON with a simple and straightforward API while leaving more complex features like parsing configurations, streaming, or data-binding to the established projects in this space.

Tooting our own horn for a moment, two more things I'm very excited about are projects we in the DevRel team organize.
Over the last year, we've considerably beefed up the Inside Java Podcast:
We're back to monthly conversations with the experts in OpenJDK, but we're now almost exclusively recording them face to face, which simply makes for better conversations.
But we also expanded our scope and are now regularly talking to you, the community members who put Java into action.
These two shows are called _Ask the Architects_ and _Input/Output_, respectively, and lastly, we're also publishing the Inside Java Newscast as a podcast.
You can find all three of these shows under the umbrella of Inside Java Podcast on all major podcasting platforms, on YouTube, and on [inside.java/podcast](https://inside.java/podcast).
  
The other project that is near and dear to me is JavaOne.
It's the premiere Java conference - nowhere else will you get to meet that many OpenJDK contributors, project leads, and Java veterans.
In 2027, it takes place on March 23-25 in Redwood Shores, California.
Check out [javaone.com](https://javaone.com) to get your ticket and say "Hi" when we meet in the hallways.



4. What do you hear others in the Java community talking about?

Since my understanding of the vast and intricate Java ecosystem is comically limited to mostly just OpenJDK, this is almost exclusively what I talk to community members about.
As such my perception is clearly biased, but I can tell you that Java developers (me included 😁) generally can't shut up about Valhalla's value types, Amber's language additions, Leyden's AOT computation, and Babylon's progress towards better AI integration.
